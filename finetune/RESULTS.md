# XTTS fine-tune - results from the M5 run (2026-06-16)

The fine-tune ran end to end on the M5 (32GB, Apple M5, macOS). It worked, the
model learned, and the A/B render is done. This file is the handoff for finishing
the work on another Mac: what ran, the numbers, the kit fixes that are now in the
repo, and how to move the trained model (it is too big for git).

## TL;DR

- Full 6-epoch fine-tune finished in **73 minutes** on the M5 GPU (MPS).
- Eval loss dropped every epoch, no divergence. The model learned the speaker.
- A/B wavs are rendered. Listen test still pending (see below).
- The trained checkpoint is **5.2GB** and is NOT in git. Move it Mac-to-Mac out of
  band (AirDrop / cloud / external disk). See "Moving the model" below.

## The environment that worked

`setup.sh` resolved these (Apple Silicon, Python 3.12.13). The pins held, nothing
floated:

| package | version |
|---|---|
| torch / torchaudio | 2.6.0 |
| transformers | 4.57.6 (the `>=4.43,<5` pin) |
| coqui-tts | 0.27.5 |
| coqui-tts-trainer | 0.3.3 |
| faster-whisper | 1.2.1 |
| yt-dlp | 2026.06.09 |

`torch.backends.mps.is_available()` is True. Training and inference both run on MPS
with `PYTORCH_ENABLE_MPS_FALLBACK=1` for the few unsupported ops.

## Two kit fixes (applied in this commit)

A clean checkout failed phase 1 in two ways. Both are fixed now so the other Mac
does not rediscover them:

1. **ffmpeg is required and is not a pip dep.** yt-dlp needs it to extract wav.
   `setup.sh` now checks for it up front and tells you to `brew install ffmpeg`.
2. **yt-dlp was called as a bare command** and is only inside the venv, so running
   through `.env/bin/python` could not find it (`FileNotFoundError: yt-dlp`).
   `prepare.py` now invokes it as `python -m yt_dlp` via the same interpreter, so
   PATH does not matter.

One gotcha left documented, not code-fixed: after `TRAIN DONE` the coqui trainer
leaves orphaned DataLoader worker processes sitting at 0% CPU, which can keep the
script from exiting on its own. If you automate this, reap them
(`pkill -f finetune/.env`) or the run will look like it hangs at the finish.

## Training results

195 steps/epoch, 6 epochs, batch 3, grad-accum 4 = 1170 steps. Steady-state step
time on MPS was ~2.4-2.7s compute, ~3.0-3.5s wall-clock including data loading.
(For reference, CPU transcription in phase 1 pegged 5+ cores at 527%, training sat
at ~143%. That gap is the proof the matmuls ran on the GPU, not a CPU fallback.)

Eval loss, monotonic down, flattening by the end (so 6 epochs was a fair stop):

| epoch | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| eval avg_loss | 3.525 | 3.398 | 3.337 | 3.312 | 3.292 | 3.270 |

Training loss (running avg) fell from ~0.99 to ~0.79 over the run.

Dataset: 6 source videos, ~65 min audio, 691 per-sentence clips (588 train / 103
eval). Whisper large-v2 int8 on CPU took ~48 min to transcribe.

## The A/B render

`infer_compare.py` wrote both to `data/out/` (default line, "How will you survive
your family at Christmas?"):

- `finetuned.wav` - 4.03s, the fine-tuned model
- `zeroshot.wav` - 8.49s, stock XTTS v2 zero-shot off the same reference clip

Both are valid 24kHz mono. Note the zero-shot is 2x longer for the identical
sentence. That needs an ear to judge (is zero-shot drawing it out, or is the
fine-tune pacing tighter), the durations alone do not say. Re-render any line:

```sh
cd finetune
PATH="$(pwd)/.env/bin:/opt/homebrew/bin:$PATH" ./.env/bin/python infer_compare.py "Your test sentence."
```

## The checkpoint

In the training run dir (regenerated by `train.py`, paths also in
`data/train_result.txt`):

- fine-tuned weights: `data/run/run/training/GPT_XTTS_FT-<stamp>/best_model.pth` (5.2GB)
- fine-tuned config:  `data/run/run/training/GPT_XTTS_FT-<stamp>/config.json`
- vocab:              `data/run/run/training/XTTS_v2.0_original_model_files/vocab.json`

`infer_compare.py` finds these automatically. If it ever misfinds, set `CKPT`,
`CONFIG`, `VOCAB` env vars from `train_result.txt`.

## Moving the model to another Mac (it is NOT in git)

`best_model.pth` is 5.2GB and `data/` is 19GB total, both gitignored on purpose.
GitHub rejects files over 100MB, so the model cannot ride in the repo. Move it out
of band. Minimum bundle to render on the other Mac:

| file | size |
|---|---|
| `GPT_XTTS_FT-<stamp>/best_model.pth` | 5.2GB |
| `GPT_XTTS_FT-<stamp>/config.json` | 8KB |
| `XTTS_v2.0_original_model_files/vocab.json` | 356KB |
| one reference clip, e.g. `data/dataset/wavs/<any>.wav` | ~tens of KB |

Easiest between two Macs: AirDrop the `GPT_XTTS_FT-<stamp>` folder plus a vocab and
one reference wav. Drop them under the same `data/run/.../training/` layout on the
other Mac (or anywhere, and point `CKPT`/`CONFIG`/`VOCAB` at them). The vocab also
comes free when stock XTTS v2 downloads on first zero-shot render, so it is
optional to carry.

If you would rather not move 5.2GB: the whole thing regenerates from
`./setup.sh && ./run.sh` (~2h: ~48 min transcription + 73 min training), fully
deterministic from `sources.txt`.
